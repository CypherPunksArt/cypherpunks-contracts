CypherPunks

Contract Design, Threat Model & Invariants
CypherPunk Labs · Rev 10 · One artifact, three jobs: build kickoff, review scope, invariant test spec

This document specifies the contracts to be built, the exact deltas from the Nouns reference implementation, the randomness and ordering algorithms, the threat model actor by actor, and the numbered invariants the test suite and any external review must hold the system to. It implements the locked design in the Master Spec (Rev 2): flat 1/day, 9,800 public / 200 reserved (blind-drawn at genesis: 100 earmarked artist grants + 100 team, custodied by the project reserve Safe), cornerstones #1 and #10,000 guaranteed public, art public, each day's punk drawn at settlement — the daily reveal is the product's hook and nobody, including the team, can know tomorrow's punk today.

No proxy. No owner. No parameter setters. The privileged surface is two human-key-restricted roles, each set once in a constructor and never changeable: (1) the pause guardian (Safe) — pause() / scheduleUnpause() / unpause() as constrained above, gating only whether NEW auctions run (an in-flight auction still settles); and (2) the Splitter payeeAdmin (Safe) — proposeArtistUpdate() / cancelArtistUpdate(), which rotate the artist payee address behind a 48h public timelock (artist key-loss recovery, ruled 2026-07-16; SHARES stay 95/5 forever). The full privileged call set is {pause, scheduleUnpause, proposeArtistUpdate, cancelArtistUpdate}. Neither role can touch code, art, the draw, auction funds, or the company's immutable 95%. The one fund-redirection path is narrow and disclosed: payeeAdmin can point the artist's 5% stream at a different address, and only after 48h notice — see §Splitter and the payeeAdmin trust note. Every constant above is a compile-time constant or immutable set in the constructor. Definition, for I11 and reviewers: "privileged" means human-key-restricted. Address-gated inter-contract wiring (e.g. the AuctionHouse-only mint/burn surface on the Token) is machine wiring between immutable contracts — no key, no discretion, not privilege.

03Ordering: Daily Draw at Settlement

Design change (supersedes the Feistel full-order model): the daily order is not derivable from the genesis seed. Each day's punk is drawn in the settlement transaction itself, preserving the daily-reveal mystery for the full 27-year run. The genesis VRF seed now determines only the reserved 200 (§04).

Daily draw: lazy Fisher–Yates, without replacement

// virtual pool of the 9,800 public pieces (post-reserved-removal),
// mapping defaults mean zero initialization cost
mapping(uint16 => uint16) private pool;
uint16 private remaining = 9800;

function _drawNext() internal returns (uint16 piece) {
    uint256 rand = uint256(keccak256(abi.encode(
        block.prevrandao, address(this), nextAuctionId, remaining)));
    uint16 i = uint16(rand % remaining);
    piece = _poolVal(i);
    remaining--;
    pool[i] = _poolVal(remaining);   // swap-and-pop
    delete pool[remaining];
}
function _poolVal(uint16 i) private view returns (uint16 v) {
    v = pool[i];
    if (v == 0 && !poolSet[i]) v = publicPiece[i];  // lazy default: i-th public piece
}
  • (Reference sketch — implementation must handle the zero-value sentinel properly, e.g. store values +1, and define publicPiece[i] as the i-th design piece after removing the reserved 200.)
  • Bijection by construction: swap-and-pop sampling without replacement; every public piece drawn exactly once across 9,800 settlements.
  • O(1) per day: ~two storage slots touched per settlement.
  • Reveal timing: the piece for auction N+1 becomes knowable only inside the settlement transaction of auction N. No precomputation path exists for outsiders or the team.
  • Retrospective verifiability: every historical draw recomputes from public data (prevrandao of the settlement block, auction id, remaining count). "Check the seed" becomes "check any day."
Randomness honesty (reviewer note): prevrandao is proposer-influenceable at the margin (one-bit bias per slot, or block withholding at real cost). Exploitation requires a proposer to gain from a specific piece appearing on a specific day — but every piece goes to an open 24-hour public auction regardless, so there is no extraction, only a seconds-early information race. This is the Nouns randomness posture, accepted deliberately. Reviewers are asked to confirm no path exists where draw timing can be combined with any other mechanism for material advantage.

04Reserved Draw & Cornerstone Exclusion (genesis)

The genesis VRF seed determines exactly one thing: which 200 design pieces are reserved — via a seeded Fisher–Yates draw over the full 10,000, taking the first 200 non-cornerstone outputs (the first 100 earmarked as artist grants, the next 100 team). All 200 reserved pieces are custodied by the project reserve Safe (CP_RESERVE_TREASURY, commit 6871e40) and distributed manually post-genesis — the 100 artist-grant pieces to future etch'd-marketplace artists. The artist payee receives the 5% proceeds stream only and holds no reserved tokens.

  • Cornerstone exclusion: design pieces 1 and 10,000 are skipped by the draw if selected; the draw continues to the next output. Deterministic, seed-derived, no human hand.
  • Per-step entropy (confirmed, encoding pinned): the reserved draw's step i uses keccak256(abi.encode(seed, i)) — abi.encode, not encodePacked. The published reference script must mirror this byte-exact.
  • publicPiece materialization (confirmed): the 9,800-entry public-piece table is computed onchain from the seed during genesis (full 10,000-step Fisher–Yates in one call, ~9M gas measured, within the binding EIP-7825 per-transaction cap of ~16.78M) and written once as an SSTORE2 blob (~19.6 KB, one chunk, O(1) reads). A deployer-supplied table is forbidden — it would silently defeat the blind draw. Fallback only if implementation demands: submit-and-verify (onchain recomputation + required hash equality before acceptance).
  • Genesis state machine: VRF fulfillment writes the seed only (callback gas cap). Then a strictly ordered, permissionless, idempotent sequence: (1) materialize publicPiece blob → (2) mint artist-grants 100 (token IDs 9,801–9,900) → (3) mint team 100 (9,901–10,000) — both tails to the reserve Safe → (4) open auction #1. Out-of-order calls revert; completed steps revert on re-call; auction #1 cannot open until all prior steps complete. This sequence is dedicated audit surface with its own test file and is replayed in the seed-ceremony rehearsal.
  • The remaining 9,800 pieces form the public pool for the daily draw (§03). Public auction mints token IDs 1–9,800 ascending, one per settlement.
  • Publishing the seed verifies the blind reserved draw and leaks nothing about the daily order, which does not derive from it.
Note on ID semantics: token ID = auction sequence (Nouns model). Design-piece numbers are a separate metadata attribute (piece). The cornerstone guarantee concerns design pieces 1 and 10,000, not token IDs. Frontend labels both (Master Spec §09).

05VRF Integration & Lock Ordering

  • Chainlink VRF v2.5 subscription, mainnet. One request, ever — its sole purpose is the reserved-200 draw (§04). Daily ordering never touches an oracle (§03).
  • Lock ordering by construction: the trait table (Descriptor piece pages), constants, and all algorithm code are immutable at deploy. The VRF request can only be made after deployment (it is a function of the deployed contract). Therefore no execution path exists in which the seed is known before the rules are locked.
  • Write-once, seed-only fulfillment: fulfillRandomWords writes the seed exactly once, guarded by a seedFulfilled flag (not the seed value, so a zero VRF word cannot leave the seed writable) and does nothing else (VRF v2.5 callback gas cap ≈ 2.5M — no minting, no blob work in the callback); any later fulfillment reverts. Genesis work proceeds via the permissionless state machine (§04). No function can re-request after a fulfillment (blocks seed-shopping by re-roll).
  • Stuck-request escape: if no fulfillment after RE_REQUEST_TIMEOUT = 7 days (timestamp-based — robust to missed-slot variance, and 7 days is beyond any meaningful timestamp manipulation), a permissionless reRequest() becomes callable — anyone, not the team, and still write-once on fulfillment. Covers VRF outage without creating a privileged re-roll.
  • Multiple-request semantics (pinned): after a reRequest, all outstanding request ids remain valid; the first coordinator delivery wins and every later fulfillment reverts. The alternative (newest-id-only) would let a timed reRequest invalidate an in-flight fulfillment, turning the escape hatch into a griefing tool. Disclosed residual: in the outage corner where two fulfillments are simultaneously in flight, both seeds are visible in the mempool and a block builder could choose which lands first — one bit of selection between two honest VRF outputs, affecting only the reserved draw, never the daily ordering. Accepted; reviewers asked to confirm no wider path.
  • VRF constants (pinned): VRF_CALLBACK_GAS_LIMIT = 100,000 (measured fulfillment 22.2k — ~4.5× headroom, far under the v2.5 2.5M cap); VRF_REQUEST_CONFIRMATIONS = 6; LINK-funded subscription (nativePayment = false). keyHash and subscription id are immutable constructor params — deploy-time inputs (§11).
  • Publish the seed and a reference script at genesis so anyone can verify the reserved draw; publish the daily-draw function so anyone can verify each day retrospectively (manifesto plate 07: read the contracts, check the seed).
  • Trust note for reviewers: Chainlink VRF operator liveness is a dependency for genesis timing only; it cannot influence which seed (VRF proof verified on-chain) and has no power after fulfillment.

06Auction Mechanics

  • English ascending; required outbid increase = max(2% of current bid, MIN_BID_STEP = 0.001 ETH); reserve per §01. The floor applies to outbids only; the opening bid remains anything ≥ reserve (0 is valid). Rationale: Solidity's integer floor makes 2% of a dust bid exactly 0, so without the floor an equal-value or 0-wei bid displaces the leader free of charge and, inside the anti-snipe buffer, extends the auction at zero cost. The floor restores the rule that every extension costs real money held at risk. Above 0.05 ETH the 2% term governs and behaviour is unchanged.
  • No-bid outcome (confirmed): a settlement with zero bidders (bidder == address(0)) burns the piece, Nouns-verbatim — intended contract behaviour. Note the 0-value-bid distinction (audit F5): because RESERVE_PRICE = 0, a 0-wei bid is a valid opening bid that registers a bidder and therefore prevents the burn, transferring the piece to that bidder (settlement pays no split for amount 0). This is by design and consistent with the no-reserve ethos (§01): the burn is the true no-interest outcome, and any 0/low bid keeps a piece alive instead. Ruling (2026-07-21): no-reserve is retained (ethos + marketing); the project runs an operational backstop bidder (small bid, e.g. a few cents) to claim any otherwise-unbid piece, so burns are rare in practice. The backstop is outside the trust model and appears nowhere in code or natspec; the burn path remains as the honest fallback when nothing — not even the backstop — bids.
  • settleCurrentAndCreateNewAuction() permissionless; each auction's clock starts at settlement of the prior (self-healing cadence; no wall-clock dependency; "day N" is frontend vocabulary).
  • Anti-snipe: bid inside final TIME_BUFFER extends end time to now + TIME_BUFFER. Unbounded total extension (contested pieces run until bidding stops) — confirm this is intended; an optional hard cap is a one-line constant if ever desired. Default: uncapped, per site copy.
  • Refunds: previous bidder refunded inline via _safeTransferETHWithFallback — 30k-gas raw call ignoring returndata, WETH transfer on failure. Copy verbatim from Nouns. Do not improve.
  • Proceeds: on settlement, full hammer price transfers to the immutable Splitter. The AuctionHouse holds only the current top bid at any moment.
  • Pause: halts creation of the next auction only. In-flight bidding and settlement unaffected. Unpause behind 48h timelock.

08Invariants (testable)

I1 — Bijection. Across the genesis reserved draw plus all 9,800 daily draws, every design piece is assigned exactly once — no duplicates, no gaps. (Fork test: full-walk enumeration.)
I2 — Cornerstones public. Design pieces 1 and 10,000 are never selected by the reserved draw, for any seed. (Property test across random seeds.)
I3 — Reserved counts exact. Artist set is exactly 100 and team set exactly 100; the sets never overlap.
I4 — Seed write-once, draw-once. After first fulfillment, no path alters the seed or re-runs the reserved draw; after each settlement, no path re-draws that day's piece.
I5 — Sequential mint. Public token IDs mint strictly 1,2,3…9,800, one per settlement; total minted ≤ 10,000; no mint function outside auction walk + genesis tail batches.
I6 — One live auction. Exactly one auction active at all times between genesis and final settlement (except while paused between auctions).
I7 — Balance integrity. AuctionHouse ETH balance == current top bid after every state transition. No stranded funds, ever.
I8 — Settle liveness. Once ended, settlement succeeds for any caller, in every reachable state, including paused, including hostile top bidder.
I9 — Refund liveness. No refund recipient can cause a bid to revert or cost the new bidder unbounded gas. (Adversarial bidder suite.)
I10 — Proceeds routing. Every settlement transfers exactly the hammer price to the immutable splitter; splitter shares never change.
I11 — Privilege surface. The complete set of privileged calls is {pause, unpause-after-timelock}. Neither moves funds, changes constants, mints, or affects ordering. (Bytecode-level review item.)
I12 — Render fidelity. tokenURI output for all 10,000 pieces is deterministic and pixel-identical to the design files. (Fork test: render all, image-diff against source PNGs.)
I13 — Anti-snipe correctness. Late bids extend exactly to now+buffer; early bids never extend; extension requires a valid higher bid.
I14 — Cadence immutability. No reachable state changes duration, buffer, increment (including MIN_BID_STEP), reserve, supply, or splitter address.
I15 — Reveal opacity. The piece for auction N+1 is not computable by any external call before the settlement transaction of auction N executes. (Review item + test that no view function leaks the next draw.)
I16 — Blob fidelity. The materialized publicPiece blob is byte-identical to an onchain recomputation from the seed, and no code path accepts an externally supplied table. (Fork test asserts equality; review confirms no submission path.)
I17 — Genesis ordering. The genesis sequence (seed → blob → artist mint → team mint → auction #1) executes only in order, each step exactly once, all steps permissionless; auction #1 is unreachable until steps 1–3 complete.

09Test & Fork-Test Plan

  • Foundry invariant suite encoding I1–I14 directly; fuzzed actors (bidders, settlers, pausers) over long runs.
  • Adversarial bidder suite: revert-on-receive bot, returnbomb bot (max returndata), gas-griefer, reentrancy prober, self-outbidder, snipe-reset spammer — each asserting I8/I9/I13 hold.
  • Full-walk simulation: mainnet-fork replay of all 9,800 settlements (time-warped), asserting I5/I6/I7/I10 at every step; measures worst-case permute gas (I1 note).
  • Render-all fork test: compose all 10,000 tokenURIs on a fork; decode SVGs; pixel-diff against Jon's design files; assert I12 with zero tolerance. This is the last gate before an immutable deploy.
  • Seed ceremony rehearsal: full deploy → VRF → reserved mint → first settlements (verify daily draws) on a fork, twice, scripted, before mainnet.

10External Review Scope

  • Layer 1 (continuous, internal): adversarial review + invariant suite maintained alongside every diff (this document is its spec).
  • Layer 2 (competition): Sherlock / Code4rena / Cantina style contest. Scope: the Nouns deltas — §03 daily draw, §04 reserved draw, §05 VRF ordering, splitter routing, pause semantics. Provided artifacts: this doc, the repo, the invariant suite. Severity anchors: anything violating I1–I14 is High by definition.
  • Layer 3 (optional, boutique firm): one pass for the public letter; scheduled only if budget and calendar allow.
  • Timing: genesis date must sit after Layer 2 completion. The public countdown is a placeholder until this calendar is real — do not let the clock ship unreviewed immutable code.
